## Timestamps & the temporal protocol

The online/temporal protocol (Phase 3) needs interaction timestamps. Only **ml1m carries them**:

- `music` `user_artists.dat` = `user artist weight` — no time.
- `book` `BX-Book-Ratings.csv` = `user isbn rating` — no time.
- `restaurant`/`movie` `ratings_final` are already in the 3-column CTR format — no time recoverable from the prepared files.

So the temporal protocol will run on **ml1m now** and **Yelp2018 later** (from raw Yelp — see below). The other four are **batch-mode only** (documented per spec §3). Note also that `restaurant` (2.3M users) and `movie` (13.5M interactions) are heavy; **ml1m (753K interactions) is the lightweight debugging dataset** for the online pipeline, exactly as the spec intends.

## ml1m (MovieLens-1M) — details

- **Source:** ratings from the official GroupLens `ml-1m.zip` (`ratings.dat`, `User::Movie::Rating::Timestamp`); KG + `item_index2entity_id` from the RippleNet movie package (Microsoft Satori, rehashed). Converted by `src/preprocess_temporal.py`.
- **Format:** `ratings_final.txt` has **4 columns** `user item label timestamp`. The base loader reads only cols 0–2 (so the base model runs unchanged); Phase 3 reads col 3.
- **Positive threshold:** rating ≥ 4 → label 1 (RippleNet convention).
- **Negative sampling:** 1:1 (`--neg_ratio 1.0`), drawn from the **positive-item pool** minus each user's positives; each negative inherits a paired positive's timestamp (so it falls in the same time window). Sampling from the positive-item pool (rather than all KG items) guarantees a **contiguous item-id space** `0..n_item-1` — required by the LightGCN branch (`entity_emb_matrix[:n_item]`) and by `construct_adj` (every entity needs ≥1 triple).
- **Item count (2,254):** lower than RippleNet's reported ~2,445 precisely because of the positive-pool negative sampling above (items with zero positive ratings never enter the item space). All other figures (**users 6,036 · entities 182,011 · relations 12 · triples 1,241,995**) match RippleNet's published ML-1M numbers — confirming the conversion is correct.
- **Time span:** `timestamp_min=956703932` (2000-04-25) → `timestamp_max=1046454590` (2003-02-28).
- Machine-readable copy: `data/ml1m/stats.json`.

**Reproduce:**
```bash
# from data/ml1m: ratings.dat (GroupLens), item_index2entity_id.txt + kg.txt (RippleNet) must be present
cd src
python preprocess_temporal.py --dataset ml1m --neg_ratio 1.0 --seed 555
# base-model smoke (CPU):
python main.py --dataset ml1m --aggregator concat --n_epochs 2 --neighbor_sample_size 4 \
  --dim 16 --n_iter 1 --batch_size 4096 --adj_type norm --alg_type lightgcn \
  --model_type KGCN_LightGCN --node_dropout_flag 1 --alpha 0.5 --smoothing_steps 1 \
  --att product --runs 1 --gpu_id -1 --topk_user_num 50 --topk_k_list '[2,10,50,100]'
```

## Yelp2018 — pending (remaining Phase 2 item)

Yelp2018 is the second target. Key issue: the standard **KGAT-format** Yelp2018 (`train.txt`/`test.txt` + `kg_final.txt`) **has no timestamps** — KGAT collapsed interactions to per-user item lists. To honor the "preserve timestamps" requirement, the converter must read the **raw Yelp Open Dataset** (`review.json` carries `date`) and join it to the KGAT entity space. This is a larger download + heavier processing, so it is deferred to a hand-off and tied to the WSL2 GPU setup (Yelp2018 is the first dataset where GPU acceleration matters). Converter to be added to `src/preprocess_temporal.py` as a `yelp2018` config.
